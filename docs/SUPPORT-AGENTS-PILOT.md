## Что требуется для запуска

- Получить доступ к чтению истории нужных открытых линий через существующее
  приложение/учётную запись Bitrix либо авторизованный браузер. ACCESS_DENIED
  пока не доказывает конкретную причину: возможны права пользователя, приложения
  или доступ к отдельной линии. Не расширять права без проверки причины.
- Внести OPENAI_API_KEY в секреты выбранного сервиса, не в переписку.
- Подтвердить ID `@turkarta_support_me` и `@siddthartha`, кто основной/резервный
  по технике и кто заменяет ответственного за платежи/карты/KYC. Не подставлять
  фиктивные ID и не выдавать одного сотрудника за отдельного резервного.
- Для assist определить закрытые группы задач/QA и руководителя QA. До этого
  можно подготовить локальный пилот на обезличенной истории без Telegram-доставки.
- Перед запуском размещённого воркера применить миграции Operations до 0013
  и настроить отдельные внутренние секреты; это ещё не выполнено.

Отдельный новый Render-сервис не является обязательным условием подготовки
пилота. Сначала можно оценить обезличенные диалоги локально. Shadow-режим на
размещённом сервисе требует его настроек/миграций и расходует модельный бюджет,
хотя ответов клиентам не отправляет.

Настройка и команды: [SUPPORT-AGENTS-RUNBOOK.md](SUPPORT-AGENTS-RUNBOOK.md).

## Уточнение доступа — 2026-09-08

Владелец подтвердил: подписка Bitrix закончилась, поэтому чтение API недоступно.
На предоставленном скриншоте интеграция ID 3 «Локальное приложение» создана
Никитой Симаковым и имеет доступы CRM, «Коннекторы для внешних мессенджеров» и
«Открытые линии». Требуемая область imopenlines в настройках присутствует.
Просить добавить её повторно не требуется. Доступ конкретного пользователя
к отдельным диалогам можно проверить после восстановления REST-доступа.

До этого пилот классификации/поиска по KB можно готовить по доступным данным
Operations. Для полноценного QA необходима полная история, например выгрузка
доступных владельцу переписок. Неполные копии не считать полной историей работы
оператора. Продление подписки не выполнялось и не включено в бюджет модели $20.

Предшествовавшая проверка до подтверждения владельца:

ACCESS_DENIED сам по себе не доказывает нехватку прав на чат: официальная
документация imopenlines.dialog.get также относит его к ограничению REST API
по тарифу. Для порталов .ru нужно проверить действующую подписку, разрешающую
работу локальных приложений/REST. Полное описание вчерашнего отказа не сохранялось.
Повторная проверка сегодня остановлена до запроса Bitrix: в доступной базе нет
access token с достаточным оставшимся сроком. Refresh token не использовался.

Проверить существующую интеграцию в «Разработчикам → Интеграции»: её создателя,
доступ imopenlines, затем доступ соответствующего пользователя к истории
разговоров. Настройки ролей находятся в «Контакт-центр → канал открытой линии →
Права доступа → Настроить»; они действуют на все открытые линии. Сначала выяснить
текущую конфигурацию и подписку; не покупать подписку и не менять роли на основании
одного кода ошибки.
